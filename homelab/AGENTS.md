# Homelab

- This is GitOps infrastructure, not an application build: Kubernetes resources live in `k8s/`; `terraform/proxmox/` and `bootstrap/` are currently placeholders.
- Manage Kubernetes resources with Kustomize manifests reconciled by Flux. Do not introduce Helm charts, HelmReleases, or Helm-based installs; vendor pinned upstream Kubernetes manifests when needed and customize them with Kustomize.
- Store Kubernetes application and platform credentials in 1Password and synchronize them with External Secrets Operator (ESO) `ExternalSecret` resources. Do not commit Kubernetes `Secret` manifests or manage app credentials with manual `kubectl create secret`; the out-of-band token required to bootstrap ESO is the exception.
- App resources belong in `k8s/apps/<app>/base/` with cluster-specific changes in `overlays/dev/` and `overlays/prod/`. Cluster Flux roots under `k8s/clusters/<cluster>/flux/` decide what actually reconciles; dev and prod selections differ.
- For pod-to-pod or pod-to-service requests within the cluster, prefer the Kubernetes Service DNS name (`<service>.<namespace>.svc.cluster.local`) over a public hostname. Public DNS may not resolve from pods, and routing through the public ingress is unnecessary. Keep public URLs for browser-facing links and redirects; for OIDC, the authorization endpoint is browser-facing, while token, user-info, and JWKS requests are server-to-server and should use the in-cluster Service address when the provider is hosted in this cluster.
- Use the root Bazel workspace for dev lifecycle commands. `bazel run //homelab/k8s/clusters/dev:up` creates the one-node Talos QEMU dev cluster on `10.200.0.0/24` and seeds the out-of-band 1Password token; it requires QEMU, `talosctl`, `kubectl`, `curl`, `jq`, `op` signed in, and sudo authorization. QEMU state is in `~/.talos/homelab-dev-qemu`; Talos credentials and kubeconfig stay in the ignored `k8s/clusters/dev/.state/`. The dev `flux` target installs Flux on Talos; do not run it until any old kind Flux reconciliation is deliberately stopped. `bazel run //homelab/k8s/clusters/dev:down` destroys only the Talos QEMU cluster and leaves kind untouched.
- Dev database-backed apps need the separate Docker PostgreSQL first: `docker compose -f homelab/k8s/clusters/dev/external/postgres/docker-compose.yaml up -d`. Its named volume persists; `down -v` deletes its data.
- Use `source homelab/k8s/scripts/set-context.sh dev` for Talos and `source homelab/k8s/scripts/set-context.sh kind` for the retained kind cluster during migration. Generated `.state` data and credentials are local; never commit them.
- Prod Flux bootstrap applies `homelab/k8s/platform/flux/install` before `homelab/k8s/clusters/prod/flux`. Treat prod-context operations as live infrastructure changes; credentials and Terraform state must stay out of Git.
- Consult `readme.md` for the verified environment, secret-bootstrap, and operational details; it is the source for prerequisites and prod context/vault variables.
